# Mixed-Winning Playbook

## 1. 현재 mixed-winning 데이터를 어떻게 해석할 것인가

현재 확보한 `mixed-winning` 샘플은 실제 외부 API를 호출해 얻은 결과다.

- 대중교통 경로: `ODsay`
- 도보/마이크로모빌리티 이동시간: `TMAP`
- 자전거 정류소/가용성: `서울시 따릉이`

즉, 수동으로 만든 더미 결과가 아니라 실제 서울 O/D 좌표를 기준으로 엔진이 계산한 결과다.

다만 현재 데이터셋은 아래처럼 표현하는 것이 정직하다.

- `mixed가 실제로 이기는 대표 사례를 확보했다`
- `추천 성향(RELIABILITY / TIME_PRIORITY)에 따라 추천 결과가 달라지는 것을 확인했다`
- `mixed-winning 표본 수는 7건까지 확보했지만, 아직 목적지 유형 다양성은 더 필요하다`

포트폴리오/발표에서 권장하는 표현:

- `실 API 기반 실험에서, 특정 O/D에서는 TIME_PRIORITY 모드가 대중교통보다 빠른 mixed 경로를 실제로 추천하는 사례를 확인했다.`
- `같은 샘플에서도 RELIABILITY 모드는 대중교통을 유지했으며, 이를 통해 추천 성향 분리가 실제 동작함을 검증했다.`

피해야 할 표현:

- `혼합 경로가 일반적으로 더 우수하다`
- `공공자전거 조합이 대중교통보다 항상 낫다`

## 2. 현재 확보한 대표 mixed-winning 의미

현재 `mixed-winning` 샘플은 아래 메시지를 보여주는 데 충분하다.

1. 엔진은 mixed 경로를 무조건 밀지 않는다.
2. mixed 경로가 실제로 빠른 경우에는 `TIME_PRIORITY`에서 추천이 가능하다.
3. 같은 샘플에서도 `RELIABILITY`는 대중교통을 유지할 수 있다.
4. 즉 이 프로젝트는 단순 랭킹이 아니라 `추천 정책`을 가진 엔진이다.

## 3. 아직 부족한 점

아래 세 가지가 더 확보돼야 `데이터가 충분하다`고 말하기 쉽다.

1. mixed-winning 샘플 유형 확대
2. 샘플 유형 다양화
3. no-mixed 샘플 분리

권장 목표:

- mixed-winning: `5~8건` 확보 완료, 다음은 유형 다양화
- mixed-opportunity: `8~12건`
- no-mixed: `4~6건`

## 4. mixed-winning을 더 찾기 위한 탐색 전략

무작정 임의 좌표를 넣는 방식은 외부 API 호출만 많이 쓰고 효율이 낮다.
다음 유형 중심으로 찾는 것이 좋다.

### A. 공원/캠퍼스/박물관 내부 목적지

특징:

- 정류장/역과 실제 목적지 사이가 벌어져 있음
- 마지막 500m~1.2km가 애매함
- 자전거 직행 또는 라스트마일 조합이 유리할 수 있음

예시 후보:

- 한강공원 내부
- 월드컵공원 내부
- 서울숲 내부
- 올림픽공원 내부
- 대형 캠퍼스 내부
- 박물관/공원형 문화시설

### B. 역세권 밖 주거지 -> 역/거점 이동

특징:

- 첫 이동이 대중교통 접근보다 개인/공공 이동수단에 유리할 수 있음
- 퍼스트마일 mixed가 나올 가능성이 있음

예시 후보:

- 경사 있는 외곽 주거지
- 버스 배차가 성기고 역 접근이 애매한 지역
- 역까지 도보가 길지만 자전거 대여소는 가까운 지역

### C. 환승을 줄일 수 있는 구간

특징:

- baseline 대중교통은 환승 2회 이상
- mixed는 환승을 1회 줄이면서 시간도 줄일 수 있음

중점 확인:

- `환승 수 감소`
- `접근 도보 증가가 과도하지 않은지`

### D. 비용 절감이 같이 가능한 구간

특징:

- 버스/지하철보다 따릉이 직행 또는 짧은 조합이 오히려 저렴
- `TIME_PRIORITY`와 `비용`이 동시에 좋아지면 매우 좋은 케이스

## 5. 샘플 추가 시 운영 원칙

### 우선순위 1. 실생활 좌표

- 역/정류장 정확한 좌표를 출발/도착으로 쓰지 않음
- 주거지/업무지/상업지/공원 내부처럼 실제 생활권 오프셋 좌표 사용

### 우선순위 2. 짧은 batch로 검증

- 한 번에 큰 샘플셋을 돌리지 말고 3~4건 단위로 먼저 검증
- 외부 API quota를 생각해 `후보 확인 -> 샘플 파일 반영` 순서 유지

### 우선순위 3. 샘플 카테고리 분리

- `mixed-winning`
- `mixed-opportunity`
- `no-mixed`

세 파일을 섞지 않고 목적별로 관리

## 6. 다음 실험 추천 절차

1. 후보 O/D 3~4건 선정
2. `RELIABILITY`로 먼저 확인
3. `TIME_PRIORITY`로 비교
4. 아래 기준으로 분류

- mixed 추천됨 -> `mixed-winning`
- mixed 대안은 있으나 추천 안 됨 -> `mixed-opportunity`
- mixed 대안 자체가 없음 -> `no-mixed`

5. 대표 케이스만 문서/README에 반영

## 7. README/포트폴리오용 바로 쓰는 문장

### 짧은 문장

- `실 API 기반 실험에서, TIME_PRIORITY 모드는 일부 O/D에서 대중교통보다 빠른 mixed 경로를 실제로 추천했다.`

### 비교 강조 문장

- `같은 O/D에서도 RELIABILITY 모드는 대중교통을 유지하고, TIME_PRIORITY 모드는 mixed 경로를 추천하는 사례를 확보해 추천 정책 차이를 검증했다.`

### 한계 포함 문장

- `현재 mixed-winning 사례는 대표 사례 수준으로 확보되어 있으며, 일반성을 높이기 위해 샘플 유형과 수를 추가 확장 중이다.`
