# ADR-003: 카셰어존은 MobilityType이 아닌 MobilityHub로 모델링

## Status
Accepted (2026-03-10)

## Context

초기 MaaS 확장 기획에서 **카셰어 사업자/그린카** 같은 카셰어를 경로의 일부로 통합하려 했다.
직관적 접근은 **`MobilityType.CARSHARE`** 로 타입을 하나 추가하고,
출발지에서 카셰어존까지 걸어가 → 차를 타고 환승역까지 → 대중교통 환승하는 시나리오를 만드는 것이다.

그러나 실제 구현 검토 중 다음 제약을 발견:

1. **TAGO 카셰어 API는 위치 정보만 제공**: 실시간 차량 가용성/예약 불가
2. **왕복 반납 모델**: 카셰어 사업자는 원칙적으로 픽업 위치로 돌아와야 함 (편도는 일부 편도존만)
3. **카셰어가 route leg가 되려면**: 실시간 재고, 반납 위치 검증, 결제 연동 필요 → 단순 포트폴리오 규모 초과
4. **위 조건 없이 Leg로 넣으면**: "존재하는지도 모르는 차"를 경로에 포함하는 꼴 → 품질 저하

또한 카셰어존 위치 자체는 **환승 허브로서 가치**가 있다:
- 카셰어존이 많은 역 = 이동수단 선택지 풍부 = 좋은 환승 거점
- 이 정보는 **후보 지점 선택**에 가중치로 반영할 수 있음

## Decision

**카셰어를 `MobilityType`이 아닌 `MobilityHub`로 모델링**.

### 구조
```
MobilityType (이동수단 자체, route leg 생성):
  - DDAREUNGI
  - PERSONAL_EBIKE
  - PERSONAL_KICKBOARD
  - KICKBOARD_SHARED (비활성)
  ※ CARSHARE 추가 안 함

MobilityHub (환승 거점, 후보 지점 가중치):
  - SUBWAY_STATION
  - BUS_STOP
  - BIKE_STATION
  - CARSHARE_ZONE            ← 여기에 추가
  - CHARGING_STATION         ← 확장 여지
  - PARKING
```

### 사용 방식
- `CandidatePointSelector`가 환승 후보 지점을 고를 때
  **근처에 `CARSHARE_ZONE` 허브가 있으면 가중치 부여**
- Leg 자체는 대중교통 + 따릉이 + 개인 PM 그대로
- 결과: "카셰어존 근처 역을 환승점으로 선호하는 경로" 추천

## Consequences

**Pro:**
- **허구 데이터 제거**: 실시간 재고 없는 카셰어가 Leg로 안 들어감
- **확장성**: 나중에 EV 충전소(C-1), 주차장 등 **허브 타입만 추가**하면 됨
- **도메인 분리 명확**: 이동수단(Leg) vs 환승 거점(가중치) 분리
- **파트너십 API 확보 시**: 그때 `MobilityType.CARSHARE` 추가하면 되고 기존 허브 모델 유지

**Con:**
- **"카셰어를 실제로 타는 경로"는 현재 추천 불가**
- 사용자 관점에서는 허브 가중치 효과가 **간접적** (즉각 가시성 낮음)
- 허브 가중치 로직이 복잡해짐 (단순 Leg 추가보다 설계 고민 많음)

## Alternatives Considered

### 대안 A: `MobilityType.CARSHARE` 추가 (왕복 가정)
- 접근: 출발지→카셰어존→환승역→카셰어존 복귀
- 장점: 직관적
- 단점:
  - 카셰어 **다운+복귀** 경로가 사용자 시나리오에 안 맞음
  - 실시간 가용성 없어 **빌릴 수 있을지 보장 불가**
  - 왕복 거리/시간이 퍼스트마일 효과 상쇄
- **채택 안 함**

### 대안 B: 편도 카셰어 전용 지원
- 접근: 카셰어 사업자 편도존, 카셰어 사업자만 대상
- 장점: 실제 편도가 가능한 구간만
- 단점:
  - 편도존 공개 API 없음 (파트너십 필요)
  - 편도 가능 구간이 제한적 (수도권 극소수)
  - 구현 복잡도 대비 커버 범위 낮음
- **채택 안 함**

### 대안 C: 카셰어 기능 완전 제외
- 장점: 가장 단순
- 단점:
  - 확장 시나리오 설명 약해짐
  - 발표관 관점: "카셰어 고려 안 했나?" 질문 대응 안 됨
- **부분 채택**: 기능은 없지만 **허브 모델 설계로 확장 가능성 증명**
